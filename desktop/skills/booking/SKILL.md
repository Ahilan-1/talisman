# Booking

Read `how_to_book.md` in this folder before the first booking of a session.

## Shape of a booking

1. **Clarify the minimum.** What, where, when, how many. Everything else can be decided while browsing.
2. **Search first, ask second.** Availability checks rarely need payment details or a seat preference.
3. **Present one recommendation**, not a menu: `2 seats, Saturday 9:40pm, ₹840 total`. Add one alternative only if it
   changes the decision (cheaper, earlier, better located).
4. **Ask once for approval** with the exact total and the cancellation terms. Then perform the booking.
5. **Confirm what happened.** Read the confirmation page, quote the reference, say where the ticket went.

## Approval gates (hard stops)

Stop and ask before: paying, placing an order, confirming a booking, adding insurance, accepting terms that charge
money, creating an account with a password you would have to store, or sending a message to a third party.

The one exception is an explicit instruction already given: "book the 9:40 show, two seats" is authorization for that
booking. It is not authorization for a different date, a different price, or extra add-ons.

## When the site fights back

- Seat maps are usually canvas or WebGL: take a `screenshot` and read the seat legend, then `find "Available"`.
- Payment pages almost always block automation. Stop, report the total, and hand the last step back to the user with
  the exact link.
- If a hold expires, say so and ask before starting again.
